# 어리버리 발표 대본 초안

목표 시간: 15분

전체 시간 배분:

- 1-6장: 문제 정의와 서비스 목표, 약 3분
- 7-8장: 전체 사용 흐름, 약 1분 10초
- 9-11장: 시나리오와 AI 생성, 약 2분
- 12-18장: 로봇, 정책, 실행 설정, 약 3분
- 19-22장: 리플레이와 AI 결과 분석, 약 2분 30초
- 23-26장: 연동 구조, 협업 방식, 확장 가능성, 약 2분
- 27-28장: 시연 전환과 마무리, 약 30초

## 슬라이드별 대본

### 1. 표지

목표 시간: 20초

대본:

안녕하세요. 저희는 어디로 딜리버리, 줄여서 어리버리 팀입니다.

저희가 만든 프로젝트는 주행 로봇 시뮬레이션과 AI 분석을 한 흐름 안에서 사용할 수 있는 플랫폼입니다.

오늘 발표에서는 내부 기술을 깊게 설명하기보다는, 로봇 학습 연구자가 실험을 준비하고 분석할 때 겪는 반복 작업을 저희 플랫폼이 어떻게 줄여주는지 중심으로 설명드리겠습니다.

### 2. 주행 로봇이란?

목표 시간: 35초

대본:

주행 로봇은 음식 배달, 순찰같은 역할을 수행하기 위해 사람과 함께 실외 보행로를 이동하는 로봇입니다.

이런 로봇은 실제 환경에서 바로 테스트하기 어렵습니다. 사람, 장애물, 도로 구조처럼 예측하기 어려운 요소가 많고, 실패했을 때 위험이나 비용도 큽니다.

그래서 상용화 단계로 가기 전에는 로봇이 운용될 다양한 위험 상황을 가상 환경에서 반복적으로 검증할 수 있어야 합니다.

### 3. 로봇 주행 실험 과정

목표 시간: 45초

대본:

로봇 주행 실험은 보통 네 단계로 진행됩니다.

먼저 현실과 비슷한 시뮬레이션 환경을 만들고, 그 안에서 로봇이 어떤 판단을 할지 행동 정책을 설계합니다. 그 다음 시뮬레이션을 실행하고, 마지막으로 결과를 분석합니다. 그리고 그 분석 내용을 바탕으로 행동 정책을 수정하거나, 추가 검증이 필요한 경우에는 환경을 편집합니다. 

문제는 이 네 단계가 각각 따로 끊어져 있으면 시간이 많이 든다는 점입니다. 환경을 만드는 데 오래 걸리고, 정책을 바꿀 때마다 다시 실행해야 하고, 실패한 이유를 로그에서 직접 찾아야 합니다. 환경 혹은 정책이 변경되었다면 이 과정이 다시 반복됩니다.

저희는 이 병목을 하나의 사용 흐름 안에서 줄이는 것을 목표로 했습니다.

### 4. 시뮬레이션 플랫폼 - 직관적인 인터페이스

목표 시간: 25초

대본:

그래서 저희는 먼저 시뮬레이션을 연구자가 직접 다루기 쉬운 애플리케이션 형태로 만들고자 했습니다.

로봇 연구자가 매번 파일을 열고 구조를 맞추는 방식이 아니라, 화면에서 환경을 보고 배치하고 수정할 수 있는 직관적인 인터페이스를 제공하는 것이 첫 번째 방향입니다.

### 5. 시뮬레이션 플랫폼 - AI 활용 작업 자동화

목표 시간: 45초

대본:

두 번째 방향은 AI를 활용한 작업 자동화입니다.

로봇 학습 연구자에게 중요한 일은 단순히 맵을 예쁘게 만드는 것이 아니라, "어떤 상황에서 정책이 실패하는지"를 빠르게 실험하는 것입니다.

그래서 저희 시뮬레이션 플랫폼에는 자연어로 원하는 주행 상황을 입력하면 시나리오 초안을 만들고, 실행 결과가 나오면 AI가 실패 패턴과 개선 방향을 정리해주는 기능이 접목되어 있습니다.

즉, 환경 구축 시간과 결과 분석 시간을 줄여서 실험 효율을 높이는 것이 핵심입니다.

### 6. 프로젝트 소개와 역할

목표 시간: 40초

대본:

저희 팀은 Unreal 트랙 3명과 AI Agent 트랙 1명으로 구성되어 있습니다.

팀원별로 제가 시나리오 시스템, 건우님이 데이터와 UX, 권선님이 로봇 제어와 센서, 현희님이 AI Agent 기능을 나누어 구현했고, 최종적으로는 사용자가 하나의 앱처럼 흐름을 따라갈 수 있게 연결했습니다.

### 7. 시스템 구성 요소

목표 시간: 35초

대본:

시스템은 크게 사용자 애플리케이션, 시뮬레이터, 로봇 행동 정책 실행부, AI 기능으로 나뉩니다.

발표에서는 구조를 자세히 파고들기보다는, 왜 이렇게 나누었는지만 말씀드리겠습니다.

사용자는 빌드된 하나의 Unreal Client에서 시나리오를 만들고 결과를 확인합니다. 시뮬레이션 실행은 별도 프로세스에서 재현 가능한 비실시간 상태 하에 진행되고, 로봇의 행동 정책은 사용자가 커스터마이즈할 수 있도록 Python으로 작성해 외부 통신으로 연결되도록 했습니다. AI 서버는 시나리오 생성과 결과 분석 기능을 담당합니다.

이렇게 나눔으로써 연구자는 복잡한 실행 구조를 직접 관리하지 않고도, 앱 안에서 실험 흐름을 이어갈 수 있습니다.

### 8. 사용 흐름

목표 시간: 35초

대본:

사용 흐름은 실제 주행 로봇 연구 과정과 맞춰 구성했습니다.

먼저 시나리오를 편집하고, 로봇의 센서와 물리 설정을 구성합니다. 그 다음 Python 스크립트로 행동 정책을 작성하고, 설정한 조건으로 시뮬레이션을 실행합니다.

실행이 끝나면 통계, 리플레이, 이벤트 기록, AI 분석을 통해 어떤 상황에서 정책이 실패하는지, 어떻게 개선할 수 있는지 확인할 수 있습니다.

### 9. 시나리오란?

목표 시간: 40초

대본:

여기서 시나리오는 단순한 맵이 아니라 하나의 실험 조건입니다.

지면, 장애물, 로봇의 출발지와 목적지, 이벤트 조건 같은 요소를 정의하고, 필요하면 값을 범위로 지정해주어 시뮬레이션 실행마다 에피소드를 샘플링할 수 있습니다.

시드 고정으로 결과가 결정론적으로 생성되도록 세팅되어 있어 연구자는 "한 번 만든 장면"이 아니라 "반복 실험할 수 있는 조건"을 만들게 됩니다. 로봇 정책을 검증하려면 이 반복 가능성이 중요합니다.

### 10. 시나리오 생성 에이전트

목표 시간: 45초

대본:

시나리오를 직접 만드는 과정은 시간이 많이 걸립니다.

그래서 사용자가 시뮬레이션을 원하는 주행 상황을 자연어로 요청하면, AI가 의도를 분석하고 시나리오 초안을 생성합니다. AI가 작성한 시나리오는 실행 가능한 형식인지 검증하고 보정하는 과정을 거치게 됩니다.

즉, 연구자는 처음부터 모든 필드를 작성하는 대신, AI가 만든 초안을 검토하고 수정하는 방식으로 시작할 수 있습니다.

### 11. 시나리오 에디터

목표 시간: 45초

대본:

사용자가 제작하는 시나리오와 AI가 생성한 시나리오 모두 동일한 포맷의 JSON 스크립트로 저장되지만 에디터를 통해 바로 화면에서 확인하고 수정할 수 있습니다.

왼쪽에서는 시나리오 구성 요소를 목록으로 보고, 팔레트에서 장애물이나 지면 요소를 선택할 수 있습니다. 중앙 뷰포트에서는 실제 배치 상태를 보고 기즈모로 이동하거나 변형할 수 있습니다.

이 부분이 중요한 이유는 AI 생성 결과를 블랙박스로 두지 않기 위해서입니다. 연구자가 의도한 실험 조건과 맞는지 직접 보고 조정할 수 있어야 실제 연구 흐름에 사용할 수 있습니다.

### 12. 주행 로봇

목표 시간: 30초

대본:

시뮬레이션의 대상이 되는 로봇은 물리 기반 주행 모델과 실제 현업에서 사용하는 센서 구성을 갖습니다.

LiDAR로 주변 객체와 거리를 감지하고, 포인트 클라우드로 시각화하며 GPS 기반으로 통행 가능 지역을 인식하는 그리드 맵을 지원합니다.

이 기능들은 로봇이 왜 특정 행동을 했는지 나중에 분석할 수 있는 근거가 됩니다.

### 13. LiDAR 센서

목표 시간: 25초

대본:

LiDAR 센서는 입체각과 스캔 주기에 따라 관측 결과가 달라집니다.

연구자는 테스트하고자 하는 로봇의 센서 조건을 바꾸면서 정책이 어떤 입력에 강하고 약한지 비교할 수 있습니다.

### 14. 로봇 스펙 설정

목표 시간: 25초

대본:

로봇 스펙도 화면에서 한눈에 조정하고 바로 미리볼 수 있게 구성했습니다.

속도, 센서 범위, 주행 관련 파라미터처럼 실험 결과에 영향을 주는 값을 UI에서 조정할 수 있고 LiDAR 센서의 감지 거리 등은 변경 사항을 직접 시각적으로 확인할 수 있습니다.

### 15. 로봇 정책 연동

목표 시간: 40초

대본:

행동 정책은 연구자의 실험 대상입니다. 로봇이 출발지부터 목적지까지 이동하기 위해 어떤 상황을 마주하면 어떻게 행동해야 하는지에 대한 규칙이 담긴 알고리즘이라고 할 수 있습니다.

이 두 레이어는 분리되어 있어 Unreal 쪽은 환경 인식, 물리 반영, 로봇 상태 전달을 담당하고, Python 스크립트가 실행되는 서버가 판단하여 로봇 동작을 실행 요청합니다.

### 16. 정책 편집

목표 시간: 25초

대본:

정책 작성은 외부 텍스트 에디터를 통해 진행할 수 있습니다.

후술할 AI 결과 분석 기능 또한 이 Python 스크립트로 작성된 정책을 직접 참조하기 때문에 사용자와 같은 컨택스트를 공유합니다.

### 17. 시뮬레이션 실행 설정

목표 시간: 30초

대본:

시나리오와 주행 로봇 스펙, 행동 정책이 준비되었다면 시뮬레이션을 위한 시드, 반복 횟수, 프레임 설정, 평가 지표 등의 설정값을 입력합니다. 

로봇 실험에서는 재현성이 중요합니다. 같은 조건에서 재현되어야만 실행 결과가 의미 있으며, 여러 에피소드를 반복 실행해 평균적인 성능과 실패 패턴을 볼 수 있어야 정책 개선 및 추가 검증의 근거로 삼을 수 있습니다.

이 설정 화면은 그런 반복 실험을 플랫폼 내에서 관리하기 위한 부분입니다.

### 18. 시뮬레이션 시스템

목표 시간: 40초

대본:

시뮬레이션 실행은 메인 화면과 분리된 프로세스에서 돌아갑니다.

이 프로세스에서는 고정 Tick을 적용해 계산을 안정적으로 만들고, 렌더링을 생략해 더 빠르게 실행할 수 있도록 했습니다. 동시에 시뮬레이션 중 로봇의 인식 정보, 행동, 충돌 같은 이벤트를 기록합니다. 사용자는 시뮬레이션 과정을 시각적으로 확인하며 진행 양상을 디버깅할 수 있습니다.

### 19. 리플레이

목표 시간: 45초

대본:

실행 후에는 리플레이로 시뮬레이션 결과를 다시 확인할 수 있습니다.

단순히 성공이나 실패만 보는 것이 아니라, 어느 시점에 로봇이 어떤 상태였는지, 센서 데이터는 어땠는지, 어떤 이벤트가 발생했는지를 같은 타임라인에서 볼 수 있습니다. 

이 기능은 로봇이 특정 상황에서 왜 특정 액션을 취했는지를 점검하는 시간을 줄이는 데 중요합니다. 굉장히 많이 누적된 에피소드들을 전부 실행하지 않아도, 문제 상황을 재현하듯 확인할 수 있기 때문입니다.

### 20. 포인트 클라우드

목표 시간: 25초

대본:

포인트 클라우드는 LiDAR가 실제로 어떤 환경을 관측했는지 보여주는 화면입니다.

정책이 실패했을 때, 그 원인이 판단 로직인지, 센서 입력이 부족했기 때문인지 구분하려면 관측 데이터를 확인해야 합니다.

이 기능은 그런 분석을 시각적으로 돕는 역할을 합니다.

### 21. 결과 분석

목표 시간: 45초

대본:

결과 분석 화면에서는 여러 에피소드로 구성된 실행 결과를 한 눈에 볼 수 있습니다.

좌측에는 아까 설명드린 한 에피소드에 대한 리플레이가 들어가 있고, 우측에는 성공률, 평균 실행 시간, 장애물과의 충돌 횟수, 제한 시간 초과 같은 중요한 지표에 대한 요약과 실험 전반에 대한 AI 분석 기능이 들어가 있습니다.

### 22. 결과 분석 에이전트

목표 시간: 50초

대본:

결과 분석 에이전트는 실행 요약, 이벤트 기록, 에피소드 결과, 행동과 상태 기록을 입력으로 사용합니다.
