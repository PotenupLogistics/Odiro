DeliveryBot Python Agent

Unreal은 실행하고, Python은 판단한다

PythonAgent는 DeliveryBot의 정책 판단과 길찾기를 Unreal 밖에서 수행하는 서버다. Unreal은 월드 상태, Grid, LiDAR, 로봇 상태를 보내고, Python이 반환한 Action을 검증해서 실행한다.

한 문장 요약

Python은 Stop, SlowDown, RePath, PathFollower, A*를 판단한다. Unreal은 Python Action을 몰래 고치지 않고, 실행 가능 여부를 검증한 뒤 실행하거나 실패로 기록한다.
Start

처음 한 번

Grid, Start, Goal, 차량/센서 설정을 Python에 전달하고 최초 A* 경로를 만든다.

Decide

주행 중 반복

현재 observation을 보내고, Python이 지금 실행할 steering/speed/brake를 반환한다.

End

끝날 때 한 번

성공 또는 실패 결과, 주행 시간, 정지 횟수, 실패 사유를 기록한다.

책임 분리

헷갈리기 쉬운 부분은 “누가 판단하고, 누가 실행하는가”다.

영역 하는 일 하지 않는 일
Unreal 월드/물리 실행, 센서 데이터 생성, Grid 전달, Action 검증, 실패 기록 정책 선택, A* 길찾기, Stop/SlowDown/RePath 판단
Python server.py HTTP 요청 수신, JSON 파싱, BotPolicy 호출, 응답 반환 정책 알고리즘을 직접 섞어 넣기
BotPolicy Start/Decide/End 흐름을 묶고 정책 호출 순서를 결정 HTTP 세부 처리
User Policy 정지, 감속, 재경로 판단 Unreal 물리 입력 직접 제어
User PathFinding A* 경로 탐색 Unreal 내부 경로 보정에 의존

확정 API 3개

1

Start

POST /scenario/start

episode 시작 시 한 번 호출한다. Grid, Start, Goal, 차량/센서 설정을 저장하고 최초 경로를 만든다.

실패 예: 시작 경로가 없으면 PATH_NOT_FOUND

2

Decide

POST /scenario/decide

주행 중 반복 호출한다. 현재 observation을 보고 Python이 Action을 반환한다.

응답: steering, targetSpeedKmh, brake, direction

3

End

POST /scenario/end

도착 또는 실패로 episode가 끝날 때 한 번 호출한다. 결과와 평가용 정보를 기록한다.

예: elapsed time, stop count, near miss count

중간 설정 변경 API는 현재 만들지 않는다. 주행 중 차량 스펙, LiDAR 스펙, 제어 모드를 바꾸는 기능은 이번 계약 범위 밖이다.

실행 순서

Unreal
DeliveryBot을 소환하고 Grid, Start, Goal, 차량/센서 설정을 준비한다.
Unreal -> Python
POST /scenario/start를 호출한다.
Python
Grid와 목표를 저장하고 A*로 최초 경로를 만든다. 실패하면 PATH_NOT_FOUND를 반환한다.
Unreal -> Python
주행 중 매 반복마다 POST /scenario/decide로 observation을 보낸다.
Python
Stop, RePath, SlowDown, PathFollower 순서로 판단하고 Action을 반환한다.
Unreal
Action을 검증한다. 값이 잘못되면 조용히 보정하지 않고 거부하거나 실패 처리한다.
Unreal -> Python
도착 또는 실패 시 POST /scenario/end로 결과를 전달한다.

폴더 구조

Policy 선택은 Unreal UI가 아니라 Python 코드 기준이다. 기본 동작 기준은 agent/user_agent.py의 create_policy()와 BotPolicy 구성으로 둔다.

Tools/PythonAgent/ server.py agent/ __init__.py contract.py user_agent.py state.py action.py pathfinding/ __init__.py astar.py policies/ __init__.py stop_policy.py slowdown_policy.py repath_policy.py path_follower.py
파일 역할 사용자 수정
server.py HTTP endpoint 처리, JSON 변환, BotPolicy 호출 거의 안 함
agent/__init__.py 패키지 진입 편의용. 필요하면 user_agent.py의 create_policy()를 re-export한다. 거의 안 함
agent/contract.py Start, Decide, End request/response 구조와 검증 규칙 가끔
agent/user_agent.py BotPolicy class와 start/decide/end 공통 판단 흐름 자주
agent/state.py episode, grid, path, policy runtime state 저장 가끔
agent/action.py Action 생성 helper 가끔
agent/pathfinding/astar.py A* 길찾기 구현 자주
agent/policies/*.py Stop, SlowDown, RePath, PathFollower 정책 자주

BotPolicy 인터페이스

Python 서버 내부에서는 HTTP 이름과 같은 3개의 method만 사용한다.

class BotPolicy:
    def start(self, request: ScenarioStartRequest, state: AgentState) -> ScenarioStartResponse:
        ...

    def decide(self, request: ScenarioDecideRequest, state: AgentState) -> ScenarioDecideResponse:
        ...

    def end(self, request: ScenarioEndRequest, state: AgentState) -> ScenarioEndResponse:
        ...

__init__.py는 무엇을 하나?

agent/__init__.py는 패키지 import를 편하게 만드는 보조 파일이다. 실제 policy 조합 기준은 user_agent.py에 둔다.

# agent/__init__.py
from .user_agent import create_policy

__all__ = ["create_policy"]

새 policy 추가 시

새 policy를 추가하거나 순서를 바꿀 때는 agent/user_agent.py의 create_policy()나 BotPolicy 구성을 수정한다.

# user_agent.py
from .policies.stop_policy import StopPolicy
from .policies.school_zone_policy import SchoolZonePolicy

def create_policy():
    return BotPolicy([
        StopPolicy(),
        SchoolZonePolicy(),
    ])

Decide 판단 순서

주행 중 반복되는 핵심 루프다. 어떤 policy가 먼저 action을 만들면 그 action을 Unreal에 반환한다.

  1. 현재 로봇 상태와 LiDAR 상태를 저장한다.
  2. StopPolicy가 즉시 정지가 필요한지 확인한다.
  3. 현재 경로가 막혔는지 확인하고, 필요하면 RePathPolicy가 A*를 다시 실행한다.
  4. SlowDownPolicy가 감속이 필요한지 확인한다.
  5. 위 정책들이 action을 만들지 않았다면 PathFollower가 현재 경로를 따라가는 action을 만든다.
  6. 실패하면 status: "error"와 명확한 PolicyError를 반환한다.
A* 실패를 단순 정지로 숨기면 안 된다. 반드시 PATH_NOT_FOUND처럼 실패 사유를 반환한다.

구현 방향

1. 계약부터 만든다

contract.py에 Start, Decide, End request/response 구조를 만든다. 필수 필드, enum, 숫자 범위를 검증한다.

2. HTTP는 얇게 둔다

server.py는 JSON을 받고, typed request로 변환하고, BotPolicy를 호출하고, response를 JSON으로 돌려주는 역할만 한다.

3. 상태는 state.py에 모은다

Grid, 현재 경로, episode id, 마지막 observation, 정책 runtime state를 한 곳에서 관리한다.

4. 사용자 알고리즘은 분리한다

A*는 pathfinding/astar.py, 정책 판단은 policies/*에 둔다. 서버 코드와 섞지 않는다.

5. action 검증을 중복해서 생각한다

Python은 잘못된 action을 만들지 않도록 helper를 쓰고, Unreal은 받은 action을 다시 검증한다.

6. debug.reason을 항상 남긴다

정지, 감속, 재경로, 실패가 왜 발생했는지 사람이 로그만 보고 이해할 수 있어야 한다.

Action 검증 규칙

필드 조건 실패 시
steering -1.0 <= steering <= 1.0 Action 거부 또는 episode 실패 기록
targetSpeedKmh 0.0 이상, 차량 최대 속도 이하 Action 거부 또는 episode 실패 기록
brake 0.0 <= brake <= 1.0 Action 거부 또는 episode 실패 기록
direction Forward 또는 Reverse Action 거부 또는 episode 실패 기록

완료 기준

  • Python Agent가 127.0.0.1:8000에서 실행된다.
  • Unreal이 /scenario/start를 한 번 호출한다.
  • Python이 Grid, Start, Goal을 저장한다.
  • Python이 A* 경로를 생성한다.
  • Unreal이 /scenario/decide를 반복 호출한다.
  • Python이 steering, targetSpeedKmh, brake, direction을 반환한다.
  • 장애물이 가까우면 SlowDownPolicy 또는 StopPolicy가 선택된다.
  • 현재 경로가 막히면 RePathPolicy가 A*를 다시 실행한다.
  • A* 실패 시 Python은 PATH_NOT_FOUND 오류를 반환한다.
  • episode가 끝나면 Unreal이 /scenario/end를 호출한다.
  • Unreal은 Python Action을 임의로 보정하지 않는다.
