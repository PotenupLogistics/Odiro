# 바꿔야 하는 테스트 모음

작성일: 2026-06-07  
마지막 갱신: 2026-06-07

이 문서는 현재 임시로 고정하거나 테스트 편의를 위해 만든 구현을 기록한다. 추후 WBP 또는 Web UI 방향이 확정되면 아래 항목을 실제 구현으로 교체한다.

## 현재 검증 완료

| 검증 항목 | 결과 | 확인 로그 |
|---|---|---|
| 정책 확정 후 Episode Start | 성공 | `POST /policy/spec/update` -> `POST /episode/start` -> `POST /policy/action` |
| 정책 사용 여부 적용 | 성공 | `enabledPolicies=4`와 `enabledPolicies=1`이 각각 Episode Start에 반영됨 |
| 정책 우선순위 적용 | 성공 | 후보가 2개일 때 priority가 낮은 `normal_path_follow`가 선택됨 |
| 선택된 정책 디버그 로그 | 성공 | Python 로그에 `selected policy id=... priority=... reason=...` 출력 |
| 정책 프리셋 JSON 파일 생성 | 성공 | `Json/Input/PolicySpecs/PolicySpec_*.json` 3개 생성 및 JSON 파싱 검증 |
| C++ 파일 기반 실행 흐름 | 성공 | `StartDeliveryBotRunWithPolicySpecFile` 호출 후 `/policy/spec/update` -> `/episode/start` -> `/policy/action` |

## 임시 구현

| 항목 | 현재 방식 | 왜 임시인가 | 교체 방향 | 확인 방법 |
|---|---|---|---|---|
| 정책 확정 시작 위치 | Level Blueprint의 NumPad 입력이 `StartDeliveryBotRunWithPolicySpecFile` 호출 | 최종 실행 UI/Web 방향이 아직 미정 | 시작 버튼 또는 실행 매니저에서 정책 파일명을 넘겨 실행 시작 | Python 로그 순서 확인 |
| 기본 정책 테스트 | `NumPadNine`에서 `SendDefaultRuntimePolicySpecUpdate` 호출 | C++에 기본 정책 조합이 하드코딩됨 | UI/Web이 만든 `policySpec`을 `SendPolicySpecUpdateJson`으로 전송 | `enabledPolicies=4` 확인 |
| Normal Only 테스트 | `NumPadEight`에서 Normal Only 정책 조합 전송 | Level Blueprint 임시 키 흐름 | 정책 프리셋 파일 또는 UI 선택 결과에서 JSON 생성 | `enabledPolicies=1`, `selected policy id=normal_path_follow` 확인 |
| 우선순위 테스트 | `NumPadSeven`에서 우선순위 테스트 정책 조합 전송 | 테스트 전용 흐름이며 실제 사용자 입력이 아님 | 정책 row UI 또는 Web에서 우선순위 편집 | `candidates=2`, `selected policy id=normal_path_follow priority=10` 확인 |
| 정책 확정 후 실행 연결 | C++에서 정책 확정 응답 성공 후 Episode Start와 policy loop 시작 | 현재는 테스트 키로만 호출 | 실행 매니저 또는 시작 버튼 흐름으로 이동 | 정책 확정 성공 후에만 `/episode/start`, 이후 `/policy/action` 호출 |
| Episode 자동 시작 제어 | `PolicyControllerComponent`의 Auto Start를 수동으로 끄고 테스트 | 최종 실행 방식이 아직 정리되지 않음 | 실행 매니저가 자동 시작 여부와 정책 확정 순서를 소유 | PIE 시작 직후 `/episode/start`가 먼저 나가지 않는지 확인 |
| 정책 디버그 표시 | Python 콘솔 로그 중심으로 확인 | 사용자 화면에서는 선택된 정책을 볼 수 없음 | Unreal 화면, 개발자 패널, 또는 Web UI에 `debug.selectedPolicyId`, `debug.reason` 표시 | `/policy/action` 응답 debug 필드 확인 |
| 정책 catalog 선택 UI | 현재는 버튼/리스트 UI 구현 보류 | WBP와 Web 중 방향 미정 | 선택된 `catalogId`로 `/policy/catalog/source` 호출 후 `/policy/catalog` 표시 | Python 로그와 catalog 응답 확인 |
| DeliveryBot 수치 조절 UI | 현재 UI 구현 보류 | Unreal WBP 또는 Web 설정 페이지 중 결정 필요 | 속도, 감속 거리, 정지 거리 등을 UI에서 받아 config/policy에 반영 | Python 상태 또는 주행 결과 확인 |
| 패키징 JSON 경로 포함 확인 | 현재는 PIE 기준으로만 검증 | 패키징 시 `Json/Input/PolicySpecs`가 실행 파일 옆에 복사되는지 아직 확인하지 않음 | 패키징 단계에서 `Additional Non-Asset Directories to Copy`에 `Json` 또는 `Json/Input/PolicySpecs` 포함 여부 확인 | 패키징 결과 폴더에 정책 JSON 파일 3개가 있는지 확인 |

## 임시 테스트 키

각 테스트는 같은 PIE 실행에서 연속으로 누르지 말고, 가능하면 PIE를 새로 시작해서 비교한다. 현재 구조에서는 정책 확정 성공 후 Episode Start도 다시 호출되기 때문이다.

| 키 | 목적 | 전송 정책 | 기대 결과 |
|---|---|---|---|
| `NumPadNine` | 기본 정책 전체 테스트 | `front_obstacle_stop`, `reroute_when_blocked`, `front_obstacle_slowdown`, `normal_path_follow` | 장애물이 약 3.2m 앞에 있으면 `front_obstacle_slowdown`, `speedKmh=0.50` |
| `NumPadEight` | 정책 사용 여부 테스트 | `normal_path_follow`만 사용 | `selected policy id=normal_path_follow`, `speedKmh=1.50` |
| `NumPadSeven` | 우선순위 테스트 | `normal_path_follow` priority 10, `front_obstacle_slowdown` priority 30 | 후보가 2개여도 `normal_path_follow` 선택 |

## 현재 임시 Policy Spec

정책 프리셋 파일 위치:

| 프리셋 | 파일 |
|---|---|
| 기본 정책 전체 | `Json/Input/PolicySpecs/PolicySpec_DefaultDelivery.json` |
| Normal Only | `Json/Input/PolicySpecs/PolicySpec_NormalOnly.json` |
| 우선순위 반전 테스트 | `Json/Input/PolicySpecs/PolicySpec_NormalPriorityTest.json` |

### NumPadNine: 기본 정책 전체

```json
{
  "policySpec": {
    "catalogId": "default_delivery",
    "catalogVersion": 1,
    "enabledPolicies": [
      { "policyId": "front_obstacle_stop", "priority": 10 },
      { "policyId": "reroute_when_blocked", "priority": 20 },
      { "policyId": "front_obstacle_slowdown", "priority": 30 },
      { "policyId": "normal_path_follow", "priority": 100 }
    ]
  }
}
```

### NumPadEight: Normal Only

```json
{
  "policySpec": {
    "catalogId": "default_delivery",
    "catalogVersion": 1,
    "enabledPolicies": [
      { "policyId": "normal_path_follow", "priority": 10 }
    ]
  }
}
```

### NumPadSeven: 우선순위 반전 테스트

```json
{
  "policySpec": {
    "catalogId": "default_delivery",
    "catalogVersion": 1,
    "enabledPolicies": [
      { "policyId": "normal_path_follow", "priority": 10 },
      { "policyId": "front_obstacle_slowdown", "priority": 30 }
    ]
  }
}
```

## 임시 테스트 절차

1. Python policy server를 `runtime` 모드로 실행한다.
2. PIE를 시작한다.
3. `NumPadNine`, `NumPadEight`, `NumPadSeven` 중 하나만 누른다.
4. Python 로그에서 `POST /policy/spec/update`가 `/episode/start`보다 먼저 나오는지 확인한다.
5. `episode start ... policySpecReceived=True enabledPolicies=N`을 확인한다.
6. `/policy/action` 로그에서 `selected policy id=...`를 확인한다.
7. 다른 키를 테스트하려면 PIE를 종료하고 다시 시작한다.

## 교체 기준

| 결정 사항 | 교체 대상 |
|---|---|
| WBP에서 정책 설정 | Level Blueprint NumPad 임시 이벤트 제거, WBP에서 `SendPolicySpecUpdateJson` 호출 |
| Web에서 정책 설정 | Web이 만든 `policySpec`을 Unreal 또는 Python으로 전달하는 API 흐름 추가 |
| 정책 설정 저장 필요 | 설정 파일, SaveGame, 또는 서버 저장소에 `policySpec` 저장 |
| 실행 중 정책 변경 필요 | 시작 전 확정뿐 아니라 실행 중 `/policy/spec/update` 호출 경로 추가 |
| 테스트 프리셋 유지 필요 | Level Blueprint 문자열 대신 별도 JSON 파일에서 policySpec 로드 |

## 다음 구현 후보

UI 방향이 아직 미정이므로 다음 단계는 Level Blueprint의 하드코딩 JSON을 줄이는 것이다. 정책 프리셋 JSON 파일과 C++ 파일 기반 실행 함수는 검증 완료됐으므로, 남은 작업은 패키징 시 JSON 파일 포함과 최종 UI/Web 호출부 교체다.

권장 순서:

1. 패키징 결과물에 `Json/Input/PolicySpecs`가 포함되는지 확인한다.
2. 패키징 환경에서도 `PolicySpec_DefaultDelivery` 같은 파일명으로 정책 실행이 되는지 확인한다.
3. WBP 또는 Web UI 방향이 확정되면 `NumPadNine/Eight/Seven` 대신 UI가 `StartDeliveryBotRunWithPolicySpecFile` 또는 동등한 실행 함수를 호출한다.
4. 추후 사용자 설정 저장이 필요하면 같은 `policySpec` JSON 형식을 저장/로드 대상으로 사용한다.

패키징 확인은 현재 보류한다. 패키징을 시작할 때 Project Settings > Packaging에서 `Additional Non-Asset Directories to Copy`에 `Json` 또는 `Json/Input/PolicySpecs`가 포함됐는지 먼저 확인한다.
