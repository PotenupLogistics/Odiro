전체 실행 흐름

MainMenu에서 산출물까지
1 사용자 선택

MainMenu에서 SimulationSetup과 EpisodeSetup을 고른다. Policy 선택은 Unreal 단계에 없다.

2 Process 실행

Platform이 simulator process를 시작하고 run id와 setup 경로를 전달한다.

3 Episode 구성

EpisodeCompiler가 JSON을 검증하고 runtime world spec으로 바꾼다.

4 Actor Spawn

지면, 장애물, 보행자, robot actor, grid bounds가 world에 배치된다.

5 정책 루프

Unreal observation을 PythonAgent가 action으로 바꾸고 Unreal이 실행한다.

6 산출물 기록

status, report, measurement log, replay record가 run id로 연결된다.

영역별 책임 지도

어디를 봐야 하는가

Platform

UI/Launch

MainMenu, simulator launch, status polling, report/log preview를 담당한다.

Shared

Contracts

SimulationSetup, RunStatus, Episode spec, replay, 공통 struct를 묶는다.

Episode

World

JSON compile, runtime actor spawn, instance id, semantic tag, 평가 흐름을 담당한다.

Runtime Actors

Execution

로봇, 보행자, 장애물, collision, movement, sensor observation이 실행된다.

PythonAgent

Policy

경로 탐색, stop/repath/slowdown/follow 판단, action 생성을 담당한다.

Artifacts

Evidence

status JSON, report JSON, measurement log, replay가 실행 근거로 남는다.

PythonAgent HTTP 계약

start, decide, end

Start

POST /scenario/start

Episode 시작 시 grid, start, goal, 초기 설정을 한 번 전달한다. Python은 최초 경로와 runtime state를 준비한다.

Decide

POST /scenario/decide

주행 중 observation을 반복 전달한다. Python은 정책 우선순위에 따라 action을 만들어 반환한다.

End

POST /scenario/end

도착 또는 실패 시 최종 상태와 metric을 전달한다. Python은 episode 상태를 정리하고 기록한다.

정책 소유권

판단과 실행의 분리

Unreal

  • Episode compile과 actor spawn
  • movement, collision, physics 실행
  • 실패, 도착, metric 검증
  • status와 log 기록

PythonAgent

  • A* 경로 탐색
  • stop, repath, slowdown 판단
  • path follower action 생성
  • episode 종료 상태 정리

산출물 흐름

실험 후 남는 근거
Status JSON
