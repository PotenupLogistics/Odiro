# World Config Output Contract

## 1. Purpose

This document describes the required structure and allowed fields for World Config JSON generated by an LLM.

## 2. Required Nested Paths

The current output contract is derived from `schemas/world_config.schema.json`. Required nested paths include:

- `schemaVersion`
- `worldId`
- `scenarioId`
- `seed`
- `map.type`
- `map.lengthCm`
- `map.sidewalkWidthCm`
- `map.surfaceCondition`
- `map.slopeDegree`
- `robot.botId`
- `robot.spawn.x`
- `robot.spawn.y`
- `robot.spawn.z`
- `robot.goal.x`
- `robot.goal.y`
- `robot.goal.z`
- `robot.policyId`
- `runtime.maxDurationSec`
- `runtime.captureReplay`
- `runtime.emitEventLog`

`robot.spawn.yawDegree` is not included because the current JSON Schema and Pydantic model do not allow it.

## 3. Allowed Top-Level Fields

- `schemaVersion`
- `worldId`
- `scenarioId`
- `seed`
- `map`
- `robot`
- `runtime`
- `obstacles`
- `pedestrians`
- `environmentObjects`

## 4. Extra Field Prohibition

The LLM must not create fields outside the schema. It must not include markdown, comments, explanations, or extra keys in the JSON response.

## 5. Scenario Requirement Binding

- `narrow_sidewalk` -> `map.sidewalkWidthCm`
- `Kickboard` -> `obstacles[].type`
- `pathBlockingHints` -> `obstacles[].blockingRatio`
- `Pedestrian` -> `pedestrians[]`
- `pedestrian_crossing` -> `pedestrians[].behavior`
